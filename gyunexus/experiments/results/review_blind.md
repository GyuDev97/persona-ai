# 블라인드 검토용 (방식 라벨 제거). 매핑은 review_key.json


## arch1: GyuNexus의 기억 검색을 임베딩 없이 정확도를 높이는 방법은 무엇일까?

### 후보 X
```
요약: GyuNexus의 기억 검색 정확도를 높이기 위해서는 문자 bigram 유사도, 중요도, 최신성 점수를 결합한 현재 방식에서 추가적인 정보 분석을 고려할 수 있다. 예를 들어, 대화 내에서 특정 키워드의 빈도를 추적하거나 사용자 피드백을 통해 중요도를 조정할 수 있다. 또한, 세션별로 저장된 주제, 날짜, 장소 정보를 활용하여 검색의 맥락을 더 강화할 필요가 있다.
아이디어:
1) 키워드 빈도 분석 — 대화 내 특정 키워드의 출현 빈도를 기록해 중요도 점수에 반영하여 검색 결과의 신뢰도를 높인다.
   위험: 사용자의 의도와 다르게 모호한 키워드의 빈도가 높을 경우 오작동 가능성
   다음 단계: 데이터베이스에 키워드 빈도 테이블 추가; 검색 알고리즘 수정
2) 사용자 피드백 시스템 도입 — 사용자가 과거 응답의 유용성을 평가할 수 있도록 시스템을 구축하여 중요도 점수를 조정하는 피드백 루프를 생성한다.
   위험: 사용자 참여 저조로 인한 데이터 부족; 피드백이 결과에 미치는 부정적 영향
   다음 단계: 피드백 인터페이스 디자인; 데이터 수집 방법 개발
3) 맥락 기반 검색 강화 — 세션 저장 정보를 활용하여 검색 시 관련 주제를 활성화해 더욱 정확한 검색 결과를 제공한다.
   위험: 세션 정보가 부족할 경우 효과 감소
   다음 단계: 세션 정보 분석 및 활용 방안 모색; 검색 알고리즘에 맥락 정보 추가
열린 질문: 현재의 검색 점수 조합의 효과성은 얼마나 되는가?; 사용자의 소통 스타일에 따라 검색 결과를 어떻게 더 개인화할 수 있는가?
주의: 현재 대화의 길이 및 정보의 양에 제한이 있다.
```

### 후보 Y
```
요약: GyuNexus의 기억 검색 정확도를 높이기 위한 여러 가지 아이디어가 제시되었지만, 특정 알고리즘이나 방법론에 대한 구체성이 부족하여 실행 가능성이 불확실한 부분이 많습니다. 이전 대화의 요약 기능, TF-IDF 가중치 조정, 사용자 피드백 루프 구축 등이 제안되었지만, 이를 구현하기 위한 명확한 절차와 방법론이 필요합니다.
아이디어:
1) 이전 대화 요약 기능 구현 — 각 대화의 주요 키워드를 추출하고, 이를 기반으로 TextRank 알고리즘을 사용하여 요약을 생성하는 방법을 제안합니다.
   다음 단계: TF-IDF 키워드 추출 방법론 조사; TextRank 알고리즘의 구체적 적용 방안 제시
2) TF-IDF 가중치 조정 — 대화의 주제 및 컨텍스트에 따라 TF-IDF 가중치를 동적으로 조정하는 머신러닝 모델을 도입하는 것을 제안합니다.
   다음 단계: 머신러닝 모델 학습을 위한 데이터 구조 설계; TF-IDF 가중치 조정 알고리즘 개발
3) 사용자 피드백 루프 구축 — 사용자가 질문 및 답변에 대한 만족도를 평가할 수 있는 UI를 구축하고 분석하여 검색 알고리즘 개선에 활용합니다.
   다음 단계: 사용자 피드백 수집을 위한 UI 설계; 수집된 데이터 분석 방법론 정의
열린 질문: 어떤 구체적인 텍스트 요약 알고리즘이나 데이터 구조가 최적의 성능을 보일 것인가?; 사용자 피드백을 어떻게 수집하고 분석할 것인가?; 'IDF'의 존재와 조건을 확인해야 함; 'TextRank'의 존재와 조건을 확인해야 함
주의: 존재가 확인되지 않은 이름: IDF, TextRank
```

### 후보 Z
```
요약: GyuNexus의 기억 검색 시스템의 정확도를 높이기 위한 몇 가지 방법론이 제안되었습니다. 주요 아이디어로는 사용자 대화에서 키워드를 추출하여 검색 가중치를 조정하고, 유사한 문구를 기준으로 검색 결과를 필터링하며, 개인화된 추천 시스템을 구축하는 방법이 포함됩니다. 그러나 일부 아이디어는 구체적인 실행 방법에 대한 추가 연구가 필요합니다.
아이디어:
1) 사용자 대화 패턴 분석 — 최근 사용자 대화에서 자주 등장하는 키워드를 분석하여 검색 가중치를 조정하는 기능 추가
   위험: 키워드 추출 과정에서의 한계로 인한 부정확한 결과
   다음 단계: 키워드 추출 방법에 대한 연구 필요
2) 유사한 문구 기준 상대적 중요도 정하기 — 유사한 문구를 기준으로 검색 결과의 중요도를 필터링하는 시스템 구현
   위험: 부정확한 검색 결과
   다음 단계: 정확한 유사성 평가 방법 연구 필요
3) 개인화된 추천 시스템 도입 — 사용자의 검색 이력을 분석하여 개인화된 추천 시스템 구축
   위험: 추천 시스템의 부정확성으로 인한 사용자 경험 저하
   다음 단계: 추천 알고리즘과 분석 방법론 구체화 필요
열린 질문: 구체적인 키워드 추출 방법은 무엇일까?; 유사한 문구 기준의 중요도를 결정하는 최적의 방법은 무엇인가?; 개인화된 추천 시스템의 세부 구현은 어떻게 이루어져야 하는가?; 'Cosine Similarity'의 존재와 조건을 확인해야 함; 'IDF'의 존재와 조건을 확인해야 함
주의: 존재가 확인되지 않은 이름: Cosine Similarity, IDF
```


## arch2: GyuNexus 에이전트 토론 결과의 품질을 자동으로 평가하는 지표를 어떻게 설계할까?

### 후보 X
```
요약: GyuNexus 에이전트 토론 결과의 품질을 자동으로 평가하기 위한 지표 설계에는 다양한 요소가 필요하다. 정확성, 일관성, 사용자 만족도, 비용 효율성 등을 포함해야 하며, 각 요소의 비중을 정해야 한다. 평가 결과는 각 라운드 후에 수집하며, 주기적으로 시스템의 자동 평가 기능을 통해 결과를 분석할 수 있어야 한다.
아이디어:
1) 정확성 지표 개발 — 에이전트 결과의 정확성을 평가하기 위해 사용자 피드백을 기반으로 하는 지표를 개발한다.
   다음 단계: 사용자 피드백 수집 방식 정의; 정확성 계산 공식 개발
2) 비용 효율성 분석 — 토론 결과의 비용 대비 효과를 분석하여 예산 관리에 활용할 수 있는 지표를 설정한다.
   위험: 비용 데이터 수집의 정밀도 문제
   다음 단계: 예산 관리 방안 설정; 비용 분석 툴 개발
3) 사용자 만족도 설문 — 토론 결과 후 사용자 만족도를 측정하기 위한 간단한 설문을 설계한다.
   다음 단계: 설문 문항 개발; 설문 배포 및 분석 계획 수립
열린 질문: 에이전트 결과의 품질 평가에 있어 사용자 요구는 무엇인가?; 어떤 메트릭을 가장 중요하게 고려해야 하는가?
주의: 기존 처리 방식과의 통합 문제가 발생할 수 있다.; 정확성을 평가하기 위한 사용자 피드백의 신뢰성을 확보해야 한다.
```

### 후보 Y
```
요약: GyuNexus 에이전트의 결과 품질을 평가하기 위한 세 가지 주요 지표가 논의되었습니다: 정확성 지표, 사용자 만족도 지표, 일관성 지표. 각 지표는 정의와 검증 방법의 명확성이 요구되며, 사용자의 신뢰를 높이기 위해 구체적인 설문 및 평가 방법을 수립해야 합니다.
아이디어:
1) 정확성 지표 — 에이전트의 결과가 사실 기반인지 검증하는 비율을 측정한다.
   위험: 정확성 평가의 신뢰성 저하 가능성
   다음 단계: 정확한 정보의 정의 및 검증 방법 구체화
2) 사용자 만족도 지표 — 사용자가 받은 결과에 대한 만족도를 설문 조사로 평가한다.
   위험: 신뢰성 있는 결과 보장 부족
   다음 단계: 설문 질문 구체화 및 평가 기준 개발
3) 일관성 지표 — 동일한 질문에 대한 답변의 유사성을 측정한다.
   위험: 일관성 평가의 실제 적용 어려움
   다음 단계: 일관성 측정 기준 및 점수 매기기 구체화
열린 질문: 정확한 정보의 정의는 무엇인가?; 사용자 만족도 질문의 구성은 어떻게 되어야 하는가?; 일관성 지표의 구체적 측정 방법은 무엇인가?
```

### 후보 Z
```
요약: GyuNexus 에이전트의 토론 결과 품질 평가를 위한 지표로 정확성, 유용성, 효율성을 제안합니다. 각 지표는 사용자 피드백을 통해 수집된 데이터를 기반으로 하며, 평가 기준을 명확히 정의하고 자동화된 피드백 수집 시스템의 구축이 필요합니다. 그러나 정확성, 유용성, 효율성 각각의 기준 설정에 대한 구체적인 방법론은 부족한 상태입니다. ⚠ 의미 검토: 요약에 증거 경고와 모순되는 서술이 있어 확정하지 않습니다. 구체적인 방법론에 대한 부족함이 요약에서 명시됨.
아이디어:
1) 정확성 평가 메트릭스 도입 — '필요한 정보'의 정의를 사용자의 질문 및 목표에 기반하여 설정하고 이를 사용자 피드백과 LLM의 응답을 비교하는 방식으로 정확성을 평가해야 함.
   위험: 기준 설정의 주관성; 피드백 데이터의 표본 오류
   다음 단계: 사용자 피드백 시스템 설계; 정확성 기준 설정 방법 연구
2) 유용성 측정 기준 설정 — 유용성을 평가하기 위해 사용자가 어떻게 정보를 활용했는지를 기반으로 사례를 수집하고 '도움이 된다'는 기준을 설정해야 함.
   위험: 유용성 기준의 모호함; 사례 수집의 비효율성
   다음 단계: 사용자 피드백 사례 수집 방법 연구; 유용성 기준 설정 방안 탐색
3) 효율성 평가 시스템 마련 — 평균 응답 시간 및 리소스 소모를 측정할 수 있는 구체적인 기준과 시스템을 구축해야 함.
   위험: 시스템 구축의 복잡성; 데이터 수집의 정확성 문제
   다음 단계: 효율성 평가 방법론 연구; 리소스 소모 측정 시스템 설계
```


## arch3: 대화 상태 라우팅에 일정·교통 같은 새 주제를 안전하게 추가하는 구조는 어떻게 만들까?

### 후보 X
```
요약: 대화 상태 라우팅 구조를 설계하기 위한 몇 가지 핵심 아이디어가 논의되었습니다. 첫째, 자동 상태 전환을 위한 명확한 조건 설정이 필요하며, 둘째, 실시간 데이터 처리를 통해 최신 정보를 유지해야 합니다. 마지막으로, 사용자 승인 절차는 직관적이면서도 보안성을 유지해야 함이 강조되었습니다.
아이디어:
1) 자동 상태 전환 조건 설정 — 사용자가 특정 질문을 할 경우 자동으로 적절한 상태로 전환하도록 명확한 조건을 설정합니다.
   위험: 예상치 못한 오류 발생 가능성
   다음 단계: 조건 설정 초안 작성; 조건에 대한 사용자 피드백 수집
2) 실시간 데이터 업데이트 주기 — 날씨 및 교통 데이터는 10분마다 신뢰할 수 있는 소스로부터 업데이트됩니다.
   위험: 잘못된 정보 제공 위험
   다음 단계: 신뢰할 수 있는 데이터 소스 조사; 업데이트 기준 수립
3) 사용자 승인 절차 설계 — 사용자의 최소한의 확인만 요구하는 직관적인 사용자 승인 절차를 설계합니다.
   위험: 보안 취약점 발생 가능성
   다음 단계: 기존 승인 절차 분석; 최소한의 확인 사항 정리
```

### 후보 Y
```
요약: 대화 상태 라우팅에 일정과 교통 정보를 추가하는 구조는 FastAPI의 RESTful API와 React 컴포넌트를 통해 통합할 수 있다. 이를 위해, 교통 및 일정 정보를 제공하는 외부 API와의 연동이 필요하며, 사용자의 요청에 따라 적절한 정보를 응답하는 로직이 구현되어야 한다. 현재 GyuNexus의 대화 시스템은 주제 및 세션 상태를 관리하고 있지만 교통 등 새로운 주제를 처리하기 위한 로직은 구현이 필요하다.
아이디어:
1) 일정 통합 기능 — 사용자의 일정 관리 API와 연동해 대화 중 발생하는 일정 관련 요구를 처리한다.
```
