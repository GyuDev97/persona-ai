# 멀티 에이전트 협업 품질 비교 실험 — 사전 고정 프로토콜

이 문서는 실험 실행 전에 고정한다. 실행 시작 시 이 파일의 SHA-256을 기록하며, 이후 평가 기준·점수 산정 방법을 바꾸지 않는다.
바꾼 것이 있으면 결과 보고서에 "사후 변경"으로 명시한다.

## 1. 비교 대상
| 코드 | 방식 | 내용 |
|---|---|---|
| A | Single LLM | 한 번의 호출로 분석하고 최종 결과(JSON)를 작성. 사실 주제에는 B/C와 같은 도구 증거 번들을 프롬프트에 제공 |
| A0 | Single LLM (증거 없음) | 사실 주제(sky1~3)에서만, 증거 번들 없이 같은 호출. Research 증거 수집의 가치를 보는 보조 대조군 |
| B | Current Multi-Agent | 현재 GyuNexus 오케스트레이터를 그대로 사용(규칙 플래너, 증거 검증 장부, 규칙 기반 충돌/반박 검증, 종료 로직) |
| C | Hybrid (실험용) | B와 같은 구조·소스를 쓰되 다음만 바꾼다. 수치·날짜·증거 ID·형식·중복은 기존 코드 검증 유지. 의미상 충돌 탐지(정규식)와 상투적 반박 정규식은 끄고 별도 LLM 검토로 대체: (1) 발언의 주장이 증거 경고와 실제로 모순인지, (2) Critic 반박의 타당성, (3) 최종 아이디어의 가치·기존 기능 중복·증거 모순 |

소스 변경 없음: C는 `experiments/` 안에서 오케스트레이터를 상속하고 모듈 속성을 실험 중에만 대체한다.

## 2. 조건
- 생성 모델: `gpt-4o-mini` (A, A0, B, C 동일). 검토/평가자 모델: `gpt-4.1-mini` (생성과 다른 모델).
- 동일 주제, 동일 배경 자료(`topics.py`의 BRIEF), 동일 사용자 기억 3건. B/C에는 배경 자료를 토론 목표에 덧붙여 전달.
- 사실 주제의 날짜·요일 정보는 동일한 컨텍스트 문장을 모든 방식에 제공. 도구 증거는 A에는 번들로, B/C에는 Research가 같은 도구로 직접 조회.
- 실행마다 독립된 임시 SQLite DB. 사용자 DB는 열지 않는다.
- 호출당 temperature는 API 기본값. 반복 실행 없음(주제×방식당 1회).
- 예산: 실제 호출 합계 상한 $0.50. 생성 단계에서 누적 $0.30을 넘기면 새 주제를 시작하지 않고, 어떤 단계든 $0.48에서 중단. 실패·중단된 실행도 결과에 기록.
- 주제는 영역별로 번갈아 실행해 중단되어도 영역 균형이 유지되게 한다.

## 3. 평가 기준과 점수 산정 (LLM 평가자)
기준 6개, 각 1~5점(정수). **종합 점수 = 6개 기준의 단순 평균.** 가중치 없음.

| 기준 | 5점 | 3점 | 1점 |
|---|---|---|---|
| accuracy 사실 정확성·증거 충실도 | 모든 주장이 배경/증거와 일치하고 불확실한 것은 불확실하다고 명시 | 사소한 근거 없는 주장이나 모호함 | 증거와 모순되거나 지어낸 사실·이름·수치가 있음 |
| specificity 구체성 | 누가·무엇을·어떻게·다음 단계가 구체적 | 일부만 구체적 | 일반론 |
| feasibility 기술적 실현 가능성 | 배경의 스택·제약에서 바로 구현/실행 가능, 범위·난이도 현실적 | 가능하나 가정이 많음 | 비현실적이거나 제약 무시 |
| novelty 차별성 | 배경에 이미 있는 기능·뻔한 조언을 넘어서는 새 각도 | 일부 새롭고 일부 뻔함 | 이미 구현된 기능이거나 뻔한 조언 |
| value 활용 가치 | 사용자가 바로 활용할 가치가 큼 | 보통 | 거의 쓸모 없음 |
| risk_review 반론·위험 검토 | 핵심 위험·한계·반례가 구체적으로 다뤄지고 과도한 비관 없음 | 형식적이거나 일부 누락 | 위험 검토가 없거나 허위·과장 |

평가 절차
- 주제마다 A, B, C 결과를 같은 형식(요약, 아이디어[제목·설명·위험·다음 단계], 열린 질문, 주의)으로 정규화하고 방식·상태 라벨·"증거 경고:" 접두어를 제거한다.
- 후보를 무작위 순서로 익명(후보 1~3) 제시하고 **순서를 뒤집어 한 번 더** 평가해 평균한다(위치 편향 완화).
- 평가자에게 길이로 점수를 주지 말고 근거 없는 주장은 감점하라고 지시한다. 결과 길이는 별도 기록해 상관을 보고한다.
- 사실 주제(sky1~3)의 후보 평가에는 증거 번들을 함께 제공한다.
- 평가자 점수는 주관적 근사치이며, 품질이 객관적으로 입증되었다고 주장하지 않는다. 원문과 블라인드 검토용 파일을 보존한다.

## 4. 코드 기반 객관 지표 (평가자와 독립)
- cost_usd, 호출 수, 프롬프트/완성 토큰, 지연 시간(벽시계, 초) — 호출 단위 측정.
- unsupported_pct (사실 주제만): 최종 텍스트의 `n%` 수치 중 증거(번들/수집된 증거) 텍스트에 없는 것의 수.
- warning_coverage (사실 주제만): 사용한 증거의 경고(강수·구름·달 밝기·조회 실패) 중 최종 텍스트가 해당 수치/도구명을 언급한 비율.
- 구조: 아이디어 수, 다음 단계가 있는 비율, 위험이 있는 비율, 총 글자 수.
- B/C 전용: 종료 원인, 라운드, 유효/거부 반박 수, 증거 수, 아이디어 상태 분포, 검토 개입 수.

## 5. 집계와 판정
- 방식별 종합 평균과 기준별 평균, 주제별 점수를 모두 제시.
- A 대비 차이: 주제별 종합 점수 차의 평균, 승/무/패(|차| < 0.25는 무), 주제 단위 부트스트랩 95% 신뢰구간(10,000회), 정확 부호검정 p값.
- 표본이 16개이고 평가자가 LLM이므로 유의수준에 의미를 두지 않고 효과 크기와 방향을 본다.

## 6. 중점 질문별 방법
1. 단일 대비 멀티: 위 5절.
2. 토론 전후 변화: B/C 각 토론의 Idea 1라운드 발언(초안)과 최종 결과를 블라인드 순서로 같은 루브릭으로 평가하고, 초안의 타당한 내용이 약화·삭제됐는지(verdict: improved/same/weakened)를 평가자가 판정.
3. Critic 효과: 2번의 verdict와 점수 변화, 거부/채택된 반박 수를 함께 본다.
4. Research 증거 가치: 사실 주제에서 A vs A0 (증거 유무), 그리고 B/C의 unsupported_pct·warning_coverage.
5. 의미 검토의 오탐 감소: 사실 주제 B/C 실행에서 모은 서술(주장·아이디어·요약 문장)과 증거 경고를 대상으로, 규칙 탐지기와 LLM 검토기를 같은 입력에 적용하고 평가자(gpt-4.1-mini)의 "실제 모순" 판정을 기준으로 정밀도·재현율 비교. 규칙이 표시한 항목은 사람이 읽을 수 있게 전문 보존.
6. 비용·지연 가치: 방식별 평균 비용·지연과 점수 차의 비를 제시.
7. 유리한 주제 유형: 영역별(과 사실/비사실, 소프트웨어/비소프트웨어)로 A 대비 차이를 나눠 제시.

## 7. 사전에 선언하는 한계
- LLM 평가자의 편향(장황함 선호, 같은 계열 모델 선호, 위치 편향)이 남는다. 평가자는 생성 모델과 다른 모델을 썼지만 편향이 없다고 보장하지 않는다.
- 주제×방식당 1회라 실행 간 변동을 모른다. 표본이 작다.
- 사실 정확성은 번들·배경 자료 기준이며 외부 현실과의 일치를 검증하지 않는다.
- 소프트웨어 주제의 "실현 가능성"은 평가자의 판단이고 실제 구현으로 확인하지 않았다.
- 같은 모델로 생성한 아이디어를 같은 계열이 검토하는 C의 검토 단계는 순환 평가 위험이 있다(검토기=gpt-4o-mini, 평가자=gpt-4.1-mini로 분리).
